# Architectural Decision Log

This log records the core design decisions, trade-offs, and rationales made during the development of the Hiver Customer Support Agent pipeline.

1. **Brand Choice (`AppleSupport`)**: Selected `AppleSupport` from the Customer Support on Twitter dataset because it represents the highest single-brand dialogue volume (>100k threads) and exhibits highly resolvable, technical intents (iOS updates, battery degradation, Wi-Fi connectivity, app crashes) rather than pure logistical delivery lookups.
2. **Intent Cluster Count Selection ($k=7$ via Silhouette Sweep)**: Rather than arbitrarily picking 8 clusters, we swept $k \in [5, 8]$ using scikit-learn's `silhouette_score` over sentence embeddings. $k=7$ achieved the global peak silhouette score (0.0373), recovering clean semantic groupings (e.g. `software_update`, `battery_charging`, `connectivity_issue`, `keyboard_autocorrect`, `account_access`, `app_crash_freeze`, `system_glitch_bug`).
3. **Clustering Strategy (HDBSCAN-First with K-Means Fallback)**: Attempted HDBSCAN first for density-based discovery without pre-specifying $k$; when high-dimensional sentence embedding density produced 93.3% noise points (>30% threshold), the pipeline gracefully fell back to KMeans with silhouette optimization.
4. **Deterministic Rules-Only Router**: Routed queries using strict, auditable Python rules (`src/router.py`) rather than an LLM router because routing decisions in customer support involve legal compliance, account security, and financial liability where non-deterministic LLM jitter cannot be tolerated.
5. **Retrieval Depth ($\text{top\_k}=3$)**: Set $\text{top\_k}=3$ historical resolutions for in-context grounding because Twitter replies are strictly capped at 280 characters; providing more than 3 reference resolutions saturated the prompt window without improving answer quality while increasing prompt token latency.
6. **4-Dimension Judge Rubric**: Structured the LLM-as-Judge around Correctness (technical accuracy), Groundedness (faithfulness to historical precedent), Tone (Apple brand empathy), and Actionability (concrete troubleshooting next steps) because composite single-score ratings mask critical operational failure modes (e.g., polite but hallucinated answers).
7. **Golden Evaluation Set Size ($N=180$)**: Sampled 180 stratified examples across 4 distinct calendar months (October 2017 – February 2018), deliberately incorporating ~20% ambiguous/adversarial edge cases (confidence < 0.65 or < 20 characters) to ensure statistical rigor while keeping manual validation tractable for a single candidate.
8. **Simple Baseline Architecture (TF-IDF + Logistic Regression)**: Used unigram/bigram TF-IDF with L2-regularized Logistic Regression and verbatim top-1 historical reply retrieval as the simple baseline because it provides an interpretable, non-neural competitive benchmark trained strictly on non-golden corpus data.
9. **Embedding Model Choice (`all-MiniLM-L6-v2`)**: Chose `sentence-transformers/all-MiniLM-L6-v2` because it produces compact 384-dimensional dense vectors, runs locally on CPU in milliseconds with zero external API fees, and delivers strong semantic clustering performance on customer support dialogues.
10. **Sentiment Tool Choice (`vaderSentiment`)**: Adopted VADER for polarity analysis because it is rule-based, runs in sub-millisecond time, handles social media slang, capitalization, and punctuation emphasis (e.g., "WORST PHONE EVER!!!"), triggering escalation whenever compound polarity drops below $-0.5$.
11. **Auto-Handle Allowlist (`[connectivity_issue, software_update, battery_charging]`)**: Restricted auto-handling to low-risk, self-serve technical domains with safe, reversible troubleshooting steps (e.g. resetting network settings, checking battery health, restarting device), strictly barring financial, hardware, or account credentials.
12. **Confidence Threshold Selection ($\tau = 0.80$)**: Calibrated the confidence cut-off at 0.80 against the validation set to balance automated throughput against human escalation risk, ensuring that vague or multi-intent queries (<0.80) are safely deferred to human agents.
13. **Exclusion of Multi-Turn Conversation History**: Deliberately constrained the agent to the first customer turn because on public Twitter/X, brand accounts triage the public inquiry and immediately transition sensitive exchanges to private Direct Messages (DMs) to collect serial numbers and PII; modeling multi-turn public dialogue creates unrealistic operational assumptions.
14. **Judge Model Family Selection (`gpt-4o-mini`)**: Standardized on `gpt-4o-mini` with deterministic temperature 0.0 for evaluation; explicitly flagged in the report that sharing the model family with the generator introduces potential self-preference bias, motivating the mandatory human-judge agreement study.
15. **Omission of Local Fallback Dependency**: Deliberately skipped bundling heavy 7B-parameter local weights (`bitsandbytes`, `accelerate`) in `requirements.txt` because recruiters run take-homes on standard CPU laptops, and heavy CUDA dependencies cause brittle installation failures. The pipeline defaults to OpenAI API with a zero-cost deterministic offline generator for instant, reproducible local evaluation.
